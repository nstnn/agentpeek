# Remote View listener

When Remote View is on in AgentPeek's saved settings, AgentPeek listens on `127.0.0.1` at the saved port, which the owner's `tailscale serve` publishes inside their tailnet. It answers only requests that carry the saved Tailscale login and Mac address the way Serve sends them, serves the viewer page and one status stream of redacted status, and ends that stream when AgentPeek quits. It is off by default: a fresh profile opens no socket. The stream shows only the exact folders saved as shared, and a source turned off in Settings leaves it at once. Settings > Remote View turns it on and off and edits the same settings; see [Remote View settings](./remote-settings.md).

## Sub-features

- `remote-vertical` follows real synthetic tool files through the session readers, saved policy, listener and two production viewer pages; browsing leaves tool files and local selection, pin/read/error state unchanged, and policy/lifecycle changes clear or resync both pages.

- `remote-off` opens no listening socket on a fresh profile.
- `remote-on` listens on `127.0.0.1` at exactly the saved port when the saved settings say on, and on no other interface.
- `remote-guards` gives a missing or other login, a foreign Host or Origin and any method other than GET a typed error with no session data; a refused `/` gets a fixed page.
- `remote-page` serves the viewer page with its Content Security Policy, and its hashed assets, to the owner's requests.
- `remote-stream` starts every stream with a complete redacted status (folder names, opaque IDs, "Session N" aliases, source health) and sends a heartbeat every 15 s.
- `remote-share` shows only the exact saved folders: the fixture's shared folder with its sessions under aliases, and nothing when no folder is saved.
- `remote-limits` bounds what a client can make it do, before any check of the login: a burst over 20 requests gets `rate-limited`, a sixth stream `busy`, oversize headers and a request too slow to arrive `bad-request`, and a POST with a large body `method-not-allowed` at once without being invited to send it. It still listens only on `127.0.0.1` at the saved port afterwards.
- `remote-source-off` sends a replacement status with a higher `generation` and no rows of a source as soon as it is turned off in Settings.
- `remote-viewer-entry` shows the viewer page's connection states in a browser: Live for the owner; Not allowed or the wrong-address page, with no data and no retry, for another login or Host; Connection lost with the last data dimmed (under the sticky header, also when the list is scrolled) while the listener is gone, then Live again with a full status; Remote View is off with the list cleared; and nothing left in browser storage or history.
- `remote-viewer-list` shows the read-only session list: a "Needs attention" group across projects (waiting, errors, new replies, oldest first) and a section per shared project with the rest, one status label per row in the desktop's wording, ages measured to the Mac's last check, a header summary such as "1 needs you · 1 new reply", source lines such as "Claude Code: no access on the Mac.", and Project and Tool filters that are page state only. It fits 320 pixels without horizontal scroll and works from the keyboard, and viewing or filtering requests nothing but `/`, its assets and one `/v2/status`.
- `remote-freshness` keeps last change separate from listener checked time: an unchanged status remains Live while valid 15 s heartbeats arrive; 45 s without a valid frame shows Connection lost and dims retained rows.
- `remote-resume` drops the stream when a page hides/freezes or the Mac sleeps; resume requests a new full status before Live. Retired stream responses cannot replace the new connection's data.
- `remote-slow-stream` holds only the newest pending status while a stream drains, closes it beyond 512 KiB or after 45 s blocked, and keeps the other four streams moving with 250 rows.
- `remote-privacy` keeps titles, labels and request identities out of logs, errors, browser storage, HTTP caches and browser session files. Labels and titles render as literal text; the page loads only its own resources, blocks workers/service workers, and cannot restore a selected project label from browser form history. Only the configured login and chosen workspace paths persist as settings.
- `remote-messages` (protocol v2, TASK-032) answers `/v2/sessions/<id>/messages` only while "Share recent messages" is on. That switch is in Settings (TASK-043, see [Remote View settings](./remote-settings.md) `remote-settings-messages`) and starts off at every launch, so until the owner turns it on a launched app answers `details-off` and every status frame carries `"details":false`; the on path, budgets, opaque-ID resolution and in-flight policy changes are covered by `src/main/remote/listener-messages.test.ts`, `src/core/remote/recent-messages.test.ts` and `src/main/remote/remote-view.test.ts`.
- `remote-viewer-messages` (TASK-033): while a status says `"details":true`, viewer rows are buttons that open that session's recent messages; otherwise they stay text. The detail shows prompts ("You"), replies ("Agent") and tool calls as a count only, with "Only the latest messages are shown." and "Shortened to fit." notices. Markdown is inert: raw HTML is visible text, links are their text, images are "Image: <alt>", nothing loads or runs. Under 960 px the detail replaces the list, from 960 px it sits beside it. "Back to sessions" and the browser/phone Back both return to the list (one history entry holding only a fixed marker). Text is dropped on Back, another session, a drop or page hide, `details:false` ("Recent messages are not shared."), the session leaving the status ("Unavailable.") and access end; it is never stored, logged or put in the URL or history.
- `remote-m2-journey` (TASK-036): the built app and the production viewer page together. With a detail open, each of these removes its text from the page at once: Share recent messages off ("Recent messages are not shared.", rows become text), Monitor Codex off and Remove project ("Unavailable."), a saved login change (Not allowed, detail closed), Remote View off ("Remote View is off", detail closed) and Quit (Connection lost, "Recent messages come back when the connection does."). Turning the source back on or adding the project again lets the still-open detail load the text again.
- `remote-quit` ends open streams with `end: shutdown` when AgentPeek quits, closes the port and exits cleanly.

## How to get to it (user POV)

- Settings > Remote View (see [Remote View settings](./remote-settings.md)), or, for these recipes, AgentPeek's saved state: `remote-view.json` in its state folder with `enabled: true`, a login, a Mac address, a port and the shared folders. AgentPeek reads it at launch.
- A source is turned off in the window: Settings > Sources > Monitor Codex. A viewer reaches it through the owner's `tailscale serve`; in verification, `curl` sends the headers Serve would add.

## Driving it with agentpeek.mjs

Preconditions:

- The user approved launching AgentPeek for this task. All data is synthetic: a generated fixture home, the login `owner@example.com` and the address `synthetic-mac.example-tailnet.ts.net`.
- A port `<port>` that is free now (for example from `node -e "const s=require('net').createServer().listen(0,'127.0.0.1',()=>{console.log(s.address().port);s.close()})"`).
- A state folder `<state>` holding `remote-view.json` with `{"version":1,"enabled":true,"ownerLogin":"owner@example.com","hostName":"synthetic-mac.example-tailnet.ts.net","port":<port>,"sharedWorkspaces":["/Users/synthetic/projects/fixture-demo"],"shareTitles":false}`. The folder is the fixture's only workspace (`CWD` in `scripts/fixture/records.mjs`); it is not a folder on this Mac. For the no-folder check use a second state folder with `"sharedWorkspaces":[]`.
- `npm run fixture -- create`, then `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs launch --label remote-listener --fixture <home> --state <state>` (the build includes the viewer), and `doctor` prints `doctor: OK`.
- Below, `-H "$OWNER"` stands for `-H 'Host: synthetic-mac.example-tailnet.ts.net' -H 'Tailscale-User-Login: owner@example.com'`.

- **Find the listener.** `lsof -nP -a -p <pid> -iTCP -sTCP:LISTEN` lists `127.0.0.1:<port>` beside the helper's two debug ports, and nothing on `*` or another address.
- **Guards.** `curl -s -w ' %{http_code}' -H 'Host: synthetic-mac.example-tailnet.ts.net' http://127.0.0.1:<port>/v2/status` prints `{"v":2,"error":"not-allowed"} 403`; with a different `Tailscale-User-Login` also 403; with the owner login and `Host: 127.0.0.1:<port>` `bad-host 421`; with `-H "$OWNER" -H 'Origin: https://evil.example'` `bad-origin 403`; with `-H "$OWNER" -X POST` `method-not-allowed 405`. None of these bodies contains `event:` or a session field. `curl -s -H 'Host: synthetic-mac.example-tailnet.ts.net' http://127.0.0.1:<port>/` prints an HTML page with the sentence "Not allowed. This page only opens for the Tailscale login set in AgentPeek on the Mac." and no script.
- **Recent messages off.** Take a 22-character `id` from the first status frame (below). `curl -s -w ' %{http_code}' -H "$OWNER" http://127.0.0.1:<port>/v2/sessions/<id>/messages` prints `{"v":2,"error":"details-off"} 403`; without the login it prints `not-allowed 403`; `/v1/status` and `/v1/sessions/<id>/messages` print `unsupported-version 404`; `/v2/sessions/abc/messages` prints `not-found 404`. No body contains message text, a title or a path.
- **Page.** `curl -s -D - -H "$OWNER" http://127.0.0.1:<port>/` answers 200 with `Cache-Control: no-store`, a `Content-Security-Policy` header with `default-src 'none'`, `script-src 'self'`, `worker-src 'none'`, `child-src 'none'` and `frame-ancestors 'none'`, and the viewer page. Each `/assets/…` path the page names answers 200 with `Cache-Control: public, max-age=31536000, immutable`.
- **Stream and sharing.** `curl -sN --max-time 17 -H "$OWNER" http://127.0.0.1:<port>/v2/status` prints first one `event: status` frame whose JSON has `"v":2`, `snapshotId`, `generation`, `observedAt`, `sentAt`, `"details":false` and `status` with `sources` (Codex and Claude Code `connected`) and one project, `"label":"fixture-demo"`, whose sessions are titled `Session 1`, `Session 2`, … with 22-character IDs, then an `event: heartbeat` frame about 15 s later with the same `snapshotId`. - **Limits.**
  - Burst: `seq 30 | xargs -P 30 -I{} curl -s -o /dev/null -w '%{http_code}\n' -H "$OWNER" http://127.0.0.1:<port>/ | sort | uniq -c` counts about 20 `200` and the rest `429`, and nothing else. Right after it, `curl -s -D - -H 'Host: synthetic-mac.example-tailnet.ts.net' http://127.0.0.1:<port>/v2/status` from a client without the login answers `429` with `Retry-After: 5` and `{"v":2,"error":"rate-limited"}`, not `not-allowed`: the rate limit comes first. Wait 3 s before the next step so the limit has refilled.
  - Sixth stream: with five `curl -sN -H "$OWNER" …/v2/status > /dev/null &` running, a sixth prints `{"v":2,"error":"busy"} 503`. Stop the five (`kill %1 %2 %3 %4 %5`).
  - Oversize headers: `curl -s -w ' %{http_code}' -H "$OWNER" -H "X-Pad: $(head -c 17000 /dev/zero | tr '\0' a)" http://127.0.0.1:<port>/v2/status` prints `{"v":2,"error":"bad-request"} 400`; with `head -c 15000` the request is served normally.

Delete `body.bin` afterwards.
  - Slow request: `time nc -d 127.0.0.1 <port>` (connect, send nothing) prints `HTTP/1.1 400` with `{"v":2,"error":"bad-request"}` and ends after about 5-6 s.
  - Afterwards, `lsof` lists the same `127.0.0.1:<port>` and nothing new, and an owner request to `/` answers 200.
  - The per-stream byte budget cannot be reached with the generated fixture alone. `npx vitest run src/main/remote/listener-limits.test.ts src/main/remote/listener-resilience.test.ts` uses a real paused TCP reader, injected delayed writes, maximum-size frames and five 250-row streams. The real paused-reader check takes about 45 s.

## Gotchas

- `curl` sends `Host: 127.0.0.1:<port>` unless told otherwise, which the listener refuses with `bad-host` by design; always pass the Mac address as Host.
- The login header is trusted as Serve's: any process on the Mac can send it. That is why every run uses synthetic data and a synthetic login.
- If `<port>` is taken when AgentPeek starts, nothing listens and it does not try another port; pick a new port and relaunch.
- A checkout without the viewer build answers `/` with `{"v":2,"error":"not-found"}`; `npm run build` builds it.
- The helper's `--remote-debugging-port=0` and `--inspect=0` also listen on loopback; tell them apart by port.
- The rate limit is global, 10 requests a second with a burst of 20. Run the limit checks last, or wait a few seconds after the burst, or the next check gets `429` instead of its own answer.
- `test:remote-browser` uses the installed Google Chrome through Playwright's `chrome` channel with a fresh temporary profile; it fails at launch without Chrome. Its page sets `Math.random` low so reconnects come within a second; real pages wait up to 30 s.
- `stop` deletes the copied state folder; the original `<state>` folder stays and is synthetic.
