# Main window

Opening AgentPeek shows one window titled AgentPeek with a sidebar, sessions list, and selected detail when navigation leaves enough content width. See navigation-visibility.md for independent toggles and current capacity boundaries. Fixture runs show a persistent banner naming the synthetic home. The first launch maximizes within the work area; subsequent launches restore saved window geometry and mode. The window cannot shrink below its minimum and restores the saved System/Light/Dark appearance choice; System is the default and follows the Mac.

## Sub-features

- `window-open` shows exactly one window, titled AgentPeek, once its content has rendered.
- `window-layout` shows Active and source health; an empty synthetic home says "No sessions yet".
- `window-size` first opens maximized within the display's work area, without macOS Full Screen, and refuses to shrink below 760 × 480.
- `window-restore` remembers normal window size/position and maximized/Full Screen choice on normal close/quit; a disconnected display cannot leave the window off screen.
- `window-appearance` uses paired Light and Dark palettes according to Settings > Appearance > Theme; System follows the Mac.
- `window-typography` uses System Monospace throughout the app content, including navigation, session text, Settings, Markdown and tool calls, with a 12-pixel base size and a compact size hierarchy.
- `window-scrollbars` uses slim platform scrollbars with neutral thumbs and transparent tracks in both themes, including the list, both transcripts and horizontal Markdown overflow.
- `window-reading-space` bounds initial titles to two lines and keeps long-message controls usable across default/minimum sizes and capacity boundaries.
- `window-split-size` uses available width for one/two details and adjacent/replacement list navigation; navigation-visibility.md defines capacity boundaries for expanded Views and the icon rail.
- `window-pane-resize` trades space between adjacent visible columns with pointer/keyboard dividers, readable minimums, cancellation/reset, and in-memory sizes across responsive modes.

## How to get to it (user POV)

- Open AgentPeek. In development that is `npm start` after `npm run build`, or `npm run dev`; the local packaged build is `dist/mac-arm64/AgentPeek.app` (see local-package.md for isolated native checks).
- Drag a window corner to resize it.
- Choose Window > Zoom to toggle maximization, or use the native green title-bar button for macOS Full Screen; close or quit, then open AgentPeek again to restore the choice.
- Choose System, Light or Dark in AgentPeek's Settings; see [Settings and appearance](./settings.md). System follows the Mac's existing appearance.
- Scroll the sessions list or a long conversation with the trackpad, mouse or keyboard; drag the scrollbar thumb to move through it.

## Driving it with agentpeek.mjs

Preconditions:

- The user approved launching AgentPeek for this task.
- Use a fresh run for launch/default-size assertions. For shared-run layout recipes, choose View > Actual Size, expand Views and reset the Sidebar width divider with Enter or a double-click; confirm 100% zoom and the default 190-pixel sidebar. Focus before resizing and observe settled page geometry before capturing.
- Before forced palette checks, record `main-eval "electron.nativeTheme.themeSource"` and restore that value afterward. Forced themes do not verify Settings selection or persistence.

- **Open.** Launch AgentPeek. Run `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs launch --label main-window`, then `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs doctor`. Launch prints a run id, and doctor prints `doctor: OK` with `one visible window: [{"visible":true,"title":"AgentPeek"}]`.
- **Layout.** Look at the window. Run `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs aria main-window-initial` and `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs screenshot main-window-initial`. The tree holds `main "Sessions"`, `heading "Active" [level=1]`, sidebar view buttons and both sources. An empty home shows "No sessions yet". At the default width the detail placeholder says "No session selected".
- **Typography (`window-typography`).** Use a populated synthetic fixture at 100% interface zoom. Open All Sessions, a conversation containing Markdown/code and a tool-call disclosure, then Settings through its button. Observe computed font families on visible text and controls with read-only `eval`: all use the shared `ui-monospace, SFMono-Regular, monospace` stack. Check the root/base size is 12px, the detail title is 16px, Markdown code is 11px and tool-call input is 10.5px. Save ARIA/PNG for the workspace and Settings in Light/Dark, including the minimum window size. Confirm readable labels, reachable controls and zero page-wide horizontal overflow. The native macOS menu and title bar retain platform-managed fonts.
- **Default size.** In a fresh profile, observe `main-eval "({bounds:BrowserWindow.getAllWindows()[0].getBounds(),maximized:BrowserWindow.getAllWindows()[0].isMaximized(),fullScreen:BrowserWindow.getAllWindows()[0].isFullScreen(),workArea:electron.screen.getDisplayMatching(BrowserWindow.getAllWindows()[0].getBounds()).workArea})"`. The window fills the work area, is maximized and is not in macOS Full Screen. With 100% zoom, the expanded 190-pixel sidebar and one detail region, the Active sessions list starts at 360 pixels. Read separator values and actual region bounds with `eval`, and capture `aria window-size-initial` plus `screenshot window-size-initial`. Drag the Sessions width separator, then press Enter or double-click it: it returns to 360 pixels. Two-detail split mode retains its separate 300-pixel list default.
- **Restore (`window-restore`).** Use an isolated profile retained across actual process restarts; `relaunch` only checks a second instance and cannot prove cold restoration. Choose Window > Zoom to leave maximization, then use the documented native-resize surrogate `main-eval "BrowserWindow.getAllWindows()[0].setBounds({x:100,y:100,width:1000,height:650})"`. Read actual settled bounds and save ARIA/PNG. Close naturally and require clean exit. Restart the same synthetic home/profile without deleting it: actual bounds and normal mode must return, with no selected session. Repeat after Window > Zoom, and, with authorized native desktop control bound to this exact fixture PID, after the native green Full Screen button and completed transition. Use the normal Close/Quit user action in each mode, capture the saved geometry metadata and reopened state, then clean every process/profile. Report native Full Screen as untested if its exact user control is unavailable; setting a flag through the inspector is not user-control acceptance. Disconnected-display recovery is covered by isolated geometry tests; live multi-display evidence requires that hardware.
- **Smallest size.** Try to make the window smaller than allowed. Run `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs main-eval "(BrowserWindow.getAllWindows()[0].setSize(400, 300), BrowserWindow.getAllWindows()[0].getSize())"`, then `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs screenshot main-window-minimum`. The result is `[760, 480]`, and the screenshot shows a 190-point sidebar and list filling the remaining width; the detail is hidden. No horizontal page overflow or clipped controls.
- **Layout boundary.** Follow navigation-visibility.md at expanded Views widths 799/800, 839/840 and 1124/1125, plus rail 985/986, with the default-size/zoom prerequisites above. Use `main-eval "BrowserWindow.getAllWindows()[0].setContentSize(<width>, 720)"` to set a page width; observe `eval "({width:innerWidth,overflow:document.documentElement.scrollWidth-innerWidth})"` and the settled visibility before capture. Capture ARIA/PNG and zero document overflow. Resizing preserves the reading target; establish the required Show Sessions/Hide Sessions state at each boundary.
- **Light appearance.** Force the light theme. Run `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs main-eval "electron.nativeTheme.themeSource = 'light'"`, then `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs eval "matchMedia('(prefers-color-scheme: dark)').matches"` and `node .agents/skills/verify-agentpeek/scripts/agentpeek.mjs screenshot main-window-light`. The media query is `false` and the screenshot shows dark text on a light background.
- **Reading space.** Follow session-detail.md's `detail-title` and `detail-long-message` journeys at default/minimum and 799/800 content widths. Capture header/transcript heights and zero page overflow before and after expansion/collapse; fixture banners reduce usable reading height. In compact detail, Back/Escape still returns to the selected row with list focus.
- **Slim scrollbars (`window-scrollbars`).** Use a populated synthetic fixture with long conversations and horizontally overflowing code/table content. Run `focus` and confirm the page is visible before keyboard scrolling. Inspect `getComputedStyle(e).scrollbarWidth` and `getComputedStyle(e).scrollbarColor` on the list, visible transcripts and overflowing Markdown: width is `thin` and track is transparent. With authorized desktop control bound to the exact synthetic instance, drag a visible thumb and scroll an overflowing code/table area horizontally; record the changed offsets and no page overflow. Report those input paths untested if the exact instance cannot be targeted. Repeat representative scrolling at 760 × 480 and in forced app Light/Dark, saving ARIA/PNG. Check readable thumb contrast, reachable controls and the short keyboard focus cue. Restore the recorded app theme source after capture.
- **Split sizes (`window-split-size`).** Follow navigation-visibility.md with two long synthetic sessions at default/minimum and both sides of each capacity boundary. Capture both themes, positive transcript height, zero overflow, title selectors only when one detail fits, and retained scroll/disclosures. Closing either pane restores the other session. Restore the recorded app theme source.
- **Resize (`window-pane-resize`).** At 1440 content pixels with two populated panes, save `aria window-pane-resize-before` and `screenshot window-pane-resize-before`. Observe the separators and controlled regions. Run `focus`, then `resize --selector '[role="separator"][aria-label="Sidebar width"]' --by 20`, and repeat for `Sessions width` with `--by -40`. Use the exact observed label for the session-title separator and drag it by 80. Save before/after widths via `eval "[...document.querySelectorAll('[role=separator]')].map(e=>({name:e.getAttribute('aria-label'),value:e.getAttribute('aria-valuenow'),min:e.getAttribute('aria-valuemin'),max:e.getAttribute('aria-valuemax')}))"`, aria and PNG. Adjacent regions trade space while active title, transcript nodes, scroll and expanded messages remain. Repeat the last drag with `--cancel`; widths return to their starting values. Click that divider, then `key ArrowLeft`, `key Shift+ArrowRight`, `key Home`, `key End` and `key Enter`: 10/40 pixel steps, minimum/maximum and default ratio. `click --selector '<observed separator>' --double` also resets it. Drag to extreme bounds, then probe either side of the capacity boundaries for the resulting sidebar width, include the minimum window size, and restore 1440 content pixels: no overflow or hidden separator tab stops, preferences recover where space permits. Close Right Pane and verify sidebar/list/detail resizing; in compact browsing only the sidebar/list divider remains. Repeat representative sizes in Light/Dark. Save `window-pane-resize-after` aria/PNG.
- **Dark appearance.** Force the dark theme. Run the same three commands with `'dark'` and the screenshot name `main-window-dark`. The media query is `true` and the screenshot shows light text on a dark background.
- **Restore.** Restore the app theme source recorded before the palette checks with `main-eval "electron.nativeTheme.themeSource = '<recorded-source>'"`. A fresh default profile returns to `system`; a shared run may have a saved Light or Dark choice. Use settings.md to verify saved appearance through the actual radios.

## Gotchas

- Screenshots cover the page only, not the title bar. Maximized size follows the display's current work area. Observe actual content size and pixel density instead of assuming fixed screenshot dimensions.
- A saved normal window position is fitted to its nearest available display. A fresh profile is centered before initial maximization; restored positions follow the user's previous geometry where it still fits.
- `setSize` stands in for dragging a corner, which this harness cannot do. It proves the minimum size and the layout at that size, not the drag itself.
- Never change the Mac's appearance setting. The `nativeTheme.themeSource` override is AgentPeek's own and ends when the app quits, but restore it before driving other features in the same run.
- Scrollbar width and overlay visibility follow Chromium/macOS behavior and the user's system preference. `thin` requests the platform's smaller variant rather than a fixed pixel width; a still screenshot may miss an auto-hidden thumb. Do not change the system scrollbar preference for verification. Computed styles alone do not prove thumb drawing, dragging or trackpad behavior.
- Expanded sidebar starts at 190 pixels; list preferences start at 360 single / 300 split. Minimum sidebar/list/detail sizes are 170/280/320 and sidebar maximum is 320. The 56-pixel rail has no divider. Capacity depends on reserved sidebar width; see navigation-visibility.md. Preferences survive toggles/resizes until quit/reload.
